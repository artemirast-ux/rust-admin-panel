# RustAdminPanel — бесплатная панель администратора для Rust-сервера

Веб-панель администратора для Rust-сервера: баны по IP/HWID, определение VPN, репорты, логи чата/убийств/подключений.
Полностью бесплатно: **Supabase** (база) + **GitHub Pages** (сайт). Плагин для Oxide/uMod на C#.

## Что входит

- `plugin/RustAdminPanel.cs` — плагин для сервера Rust (Oxide/uMod)
- `plugin/RustAdminPanel.json` — настройки плагина
- `database/schema.sql` — схема базы данных для Supabase
- `website/` — файлы сайта (кладутся на GitHub Pages)
- `.github/workflows/deploy.yml` — автопубликация сайта на GitHub Pages

## Архитектура

```
[Rust-сервер + плагин] ──HTTP──> [Supabase: Postgres + REST API]
                                       ↑
[GitHub Pages: сайт админа] ──JS───────┘
```

Плагин шлёт в базу данные об игроках и каждые 5 секунд проверяет таблицу `commands` —
если ты нажал «Бан» на сайте, плагин исполняет команду на сервере.

## Шаг 1. База данных Supabase (10 минут)

1. Зайди на **https://supabase.com** и зарегистрируйся (можно через GitHub). Бесплатный тариф не требует карты.
2. Нажми **New project**, придумай имя (например `rust-panel`), выбери любой регион, сгенерируй пароль (можно не запоминать — не пригодится).
3. Дождись создания проекта (~2 минуты).
4. В меню слева открой **SQL Editor** → **New query**.
5. Открой файл `database/schema.sql` из этой папки, скопируй **всё содержимое** и вставь в редактор.
6. Нажми **Run** (зелёная кнопка). Должно появиться сообщение `Success. No rows returned`.
7. Слева открой **Project Settings** (значок шестерёнки внизу) → **API**:
   - **Project URL** — скопируй (понадобится для плагина и сайта)
   - **anon public** key — скопируй (для сайта)
   - **service_role** key — скопируй **и никому не показывай** (для плагина; даёт полный доступ к базе)

## Шаг 2. Создать аккаунт администратора

1. В Supabase открой **Authentication** → **Users** → **Add user**.
2. Введи свой email и пароль, поставь галочку **Auto Confirm User** (или нажми confirm после создания).
3. Вернись в **SQL Editor** → **New query** и выполни, подставив свой email:

```sql
insert into admins (email, role) values ('ТВОЙ_EMAIL@gmail.com', 'owner');
```

Это даст тебе доступ к панели. Чтобы добавить второго админа — повтори команду с его email (его email должен быть зарегистрирован в Authentication).

## Шаг 3. Установка плагина на сервер

1. Скопируй `plugin/RustAdminPanel.cs` в папку `oxide/plugins/` на твоём сервере (или `carbon/plugins/` для Carbon).
2. Запусти сервер один раз — плагин создаст файл настроек `oxide/config/RustAdminPanel.json`.
3. Останови сервер (или выполни `o.reload RustAdminPanel` после редактирования).
4. Открой `oxide/config/RustAdminPanel.json` и впиши:
   - `[Panel] Supabase project URL` — твой Project URL из Шага 1
   - `[Panel] Supabase service role key` — твой service_role key из Шага 1
   - `[Panel] ProxyCheck.io API key` — можно оставить пустым (бесплатный лимит 1000 проверок в день с одного IP-адреса сервера), либо зарегистрироваться на https://proxycheck.io бесплатно и получить ключ с бóльшим лимитом
5. Выполни `o.reload RustAdminPanel`. В консоли не должно быть ошибок.

После этого плагин начнёт писать данные в базу. Проверь: в Supabase → **Table Editor** → `players` — должны появиться игроки, заходившие на сервер.

## Шаг 4. Размещение сайта на GitHub Pages

1. Зарегистрируйся/зайди на **https://github.com**.
2. Создай новый репозиторий: нажми **+** → **New repository**.
   - Имя: любое, например `rust-admin-panel`
   - Выбери **Public** (бесплатный GitHub Pages работает только для публичных репозиториев)
   - Галочку "Add a README" ставить не обязательно
   - Нажми **Create repository**
3. Загрузи файлы из папки `website/` в репозиторий (кнопка **Add file** → **Upload files**).
   Важно: внутри репозитория файлы должны лежать как в папке `website/` — `index.html`, `css/style.css`, `js/config.js`, `js/app.js`.
4. **Если ты загрузил только папку website целиком** — ничего страшно, измени путь в `.github/workflows/deploy.yml` (`path: website` уже настроен на папку `website`). Если файлы лежат в корне репозитория — поменяй `path: website` на `path: .` и удали файл `deploy.yml`, либо загрузи всё как есть.
5. Открой в репозитории `js/config.js` и впиши свои значения:
   ```js
   window.SUPABASE_URL = "https://твой-проект.supabase.co";
   window.SUPABASE_ANON_KEY = "твой_anon_public_ключ";
   ```
   (Сохрани — кнопка **Commit changes**. Анонимный ключ безопасно хранить на сайте — он работает только на чтение/запись через политики RLS, доступ к админ-функциям имеют только пользователи из таблицы `admins`.)
6. Загрузи также файл `.github/workflows/deploy.yml` (создай папку `.github`, внутри неё — `workflows`) — после этого сайт автоматически опубликуется при каждом изменении.
7. Открой **Settings** репозитория → **Pages**. В разделе **Source** должно быть выбрано **GitHub Actions**. Если стоит `Deploy from a branch` — переключи на **GitHub Actions**.
8. Через 1–2 минуты на вкладке **Actions** появится зелёная галочка, а в **Settings → Pages** — адрес твоего сайта вида:
   `https://ТВОЙ_НИК.github.io/rust-admin-panel/`

## Шаг 5. Проверка

1. Открой адрес сайта. Появится форма входа.
2. Введи email и пароль из Шага 2. Если всё верно — увидишь дашборд.
3. На сервере зайди игроком — он должен появиться в разделе **Игроки онлайн** (обновление раз в 10 секунд).
4. Нажми **Кик** — игрок вылетит с сервера в течение ~5 секунд.
5. Нажми **Бан** и выбери бан по IP — после захода с того же IP игрока сразу кикнет.

## Возможности

| Функция | Описание |
|---|---|
| Бан по IP | Игрок кикается при заходе, если его IP есть в таблице банов |
| Бан по HWID | Дополнительно к IP — пираты подделывают SteamID, HWID сложнее сменить |
| Бан по SteamID | Классический бан |
| Временные баны | 1 час / 1 день / 7 дней / 30 дней / навсегда |
| Определение VPN | Пометка в панели + опциональный аво-кик |
| Репорты | Команды `/report` в чате + автоматический парсинг F7-репортов |
| Лог чата | Все сообщения игроков |
| Лог убийств | Кто кого убил, из чего, с какой дистанции |
| Лог подключений | Кто заходил и выходил, с каких IP |
| Система мутов | Мут через панель, блокировка чата на сервере |
| Действия админов | История всех банов/киков/мутов с результатом исполнения |
| Статус сервера | Онлайна, слоты, FPS, аптайм |

## Настройки плагина (`oxide/config/RustAdminPanel.json`)

| Параметр | Описание |
|---|---|
| `Supabase project URL` | URL проекта Supabase |
| `Supabase service role key` | Секретный ключ (только для плагина!) |
| `ProxyCheck.io API key` | Ключ VPN-проверки (пусто = бесплатный лимит 1000/день) |
| `Kick players that use a VPN/proxy` | `true` = кикать игроков с VPN автоматически |
| `Command poll interval (seconds)` | Как часто плагин проверяет новые команды с сайта |
| `Chat commands` | Команды репорта в чате (по умолчанию `report`, `reports`) |
| `Report reasons` | Причины в интерфейсе репорта |
| `Cooldown between reports (seconds)` | Защита от спама репортами |
| `Auto-parse reports from F7` | Перехват игровых F7-репортов в панель |
| `SteamID for message avatar` | Аватарка бота в чате |
| `Command to send contact` | Команда связи (по умолчанию `contact`) |
| `Allow console command execution` | Разрешить выполнять консольные команды с сайта (раздел Действия) |
| `Collect kills` / `Collect chat messages` | Сбор логов убийств/чата |

## Команды в игре

- `/report <ник или steamid> <причина>` — отправить репорт (видно в панели)
- `/contact` — показать контакт админа

## Безопасность

- **service_role key** даёт полный доступ к базе — держи его только в конфиге плагина на сервере, нигде больше.
- **anon key** на сайте безопасен: через него нельзя удалить базу или обойти баны, RLS пускает только пользователей из таблицы `admins`.
- Таблица `admins` — единственный список тех, кто может войти в панель.

## Решение проблем

**Плагин пишет "RustAdminPanel is NOT configured"**
→ Не заполнены `Supabase project URL` и `service role key` в `oxide/config/RustAdminPanel.json`. Исправь и сделай `o.reload RustAdminPanel`.

**На сайте "Сервер не в сети или плагин не настроен"**
→ Плагин не может достучаться до базы. Проверь URL и ключ. Проверь, что таблица `server_status` не пустая (Supabase → Table Editor).

**Игроки не появляются в панели**
→ Таблица `players` пустая? Значит плагин не пишет в базу. Смотри консоль сервера на ошибки с пометкой `RustAdminPanel`.

**Не работает вход на сайт**
→ Пользователь должен быть в Authentication **и** в таблице `admins`. Проверь SQL из Шага 2. Проверь, что email подтверждён (Confirm User).

**Сайт не открывается / 404**
→ Settings → Pages → Source должно быть **GitHub Actions**. Проверь вкладку Actions — сборка должна быть зелёной.

**Бан не применяется**
→ Плагин проверяет таблицу `commands` раз в 5 секунд (настраивается). Подожди. В разделе **Действия** видно статус команды (`pending` → `done` / `failed`) и результат.
